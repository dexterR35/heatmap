# Marketing installation handoff

The installable unit is a selected URL, not a hostname or a whole website. The current runnable artifact is a local synthetic release. A real draft cannot be activated through this application, and its script-copy action is blocked. Do not place a local-demo collector URL on a live landing page.

## 1. Register the selected page

Use **Landing pages → Add landing page**. Paste a public URL containing only reviewed static rendering selectors. Remove personal, attribution, token, search, or account values first. Review the parsed origin, exact path and query constants. Enter a display name, stable page key and product label. Save the disabled draft.

For the supplied target, inclusion is exactly `https://go.netbet.ro/casino/?lp=halloween`. This does not include `/`, `/casino/`, `?lp=christmas`, another hostname, or duplicate `lp` parameters. Ignored query parameters are an explicit policy decision; new drafts ignore none. The local fixture explicitly ignores `utm_source`, `utm_medium`, and `utm_campaign` without retaining their values.

No real URL is fetched or instrumented by registering it. Confirm the final rendered destination, ownership, release, CMP, page-context adapter, CSP and privacy approvals separately. A redirecting host cannot observe a rendered page view at its source.

## 2. Generate and install the page-scoped host bridge

For the working synthetic example, select **Installation → Halloween casino · Demo → Copy script**. The bridge is inline host-owned JavaScript. It contains one selected-page manifest, the public routing key, the reviewed collector origin, and the actual immutable SDK filename plus SHA-384 integrity value generated by `pnpm build`.

Place it in that campaign template, or a tag-manager rule with the exact same origin/path/query conditions. The bridge independently checks those conditions. Do not use an All Pages trigger. Loading the host bridge itself creates no view identity, behavior listeners, or analytics network request.

The actual SDK download and config requests wait for BOTH host calls below:

```js
// After the URL, rendered content and release are consistent:
window.NBHeatmapHost.setContext({
  eligible: true,
  pageKey: 'casino-halloween',
  revision: 'demo-v1',
  locale: 'en-GB',
  variant: 'control',
  state: 'public-default'
});

// From the reviewed CMP analytics-category callback:
window.NBHeatmapHost.setConsent('granted');
```

These values describe the synthetic fixture. They are not verified NetBet production release or CMP values. A live integration needs its approved production values, HTTPS collector, and a separately released live-capable build. The event API currently rejects every real environment even if database flags are changed.

## 3. Connect consent and sensitive contexts

Call `setConsent('denied')` immediately on opt-out or withdrawal. Unknown consent remains inactive. The SDK drops queued events, aborts requests where possible, disconnects observers, and stops refresh timers. Already transmitted requests cannot be recalled. Later consent creates a fresh in-memory view; declined-period behavior is never replayed.

Before displaying login, registration, payment, game, account, responsible-gambling, or any other excluded UI, call:

```js
window.NBHeatmapHost.setContext({ ...currentPublicContext, eligible: false });
```

Do not infer eligibility by inspecting cookies or account DOM. The site must supply this signal. Query-only navigation invalidates the old context; call `setContext` again only after the next selected page has actually rendered. Changing an explicitly ignored attribution parameter does not create another view.

## 4. Instrument stable public elements

Only IDs and actions registered on the page are accepted:

```html
<button data-hm-id="hero-register"
        data-hm-action="registration-start"
        data-hm-exposure="cta">Explore</button>
<section data-hm-id="benefits" data-hm-exposure="section"></section>
<aside data-hm-private>Excluded subtree and coordinates</aside>
<div data-hm-ignore>Excluded interactions</div>
```

Forms and editable controls are excluded automatically. Never derive IDs from visitor text, form values, URLs, or account information. Fixed, sticky, transformed, zoomed and unsupported nested-scroll observations are not silently projected into the document map. Keyboard actions have no pixel positions.

## 5. Configure CSP and verify

Add the exact collector origin to `script-src` and `connect-src`; permit the host-owned inline bridge using your deployment's reviewed nonce/hash policy. Do not add `unsafe-inline` as a blanket workaround. Serve the SDK with the generated SRI and `crossorigin="anonymous"`; use `referrerpolicy="no-referrer"`. No wildcard origin authorizes event ingestion, and no credentialed event requests are needed.

Verify in browser network tools:

1. Consent unknown/declined: zero SDK, config, and event requests.
2. Unselected URL or duplicate/unknown selector: zero collector requests even after consent.
3. Selected public context with consent: immutable SDK, v2 config, then bounded JSON events.
4. No form values, raw URLs, raw query strings, text, account IDs or persistent visitor IDs in any event.
5. Withdrawal/ineligible state: no further requests; queue length zero.
6. `?lp=christmas` is a separate page with a separate reference; old content is never relabeled.
7. Page, revision, viewport width and document height match an approved reference. Missing references show explicit exclusions.

`window.NBHeatmap?.getStatus()` returns only bounded state/counters. `flush()` is best-effort. `204` means the collector committed, not that all possible visitor behavior was observed.

## 6. Rollback

Pause the selected page in the dashboard, or use the global collection stop. Remove its host bridge/tag and consent/context callbacks. Call `window.NBHeatmapHost?.destroy()` to tear down the current document integration and restore wrapped history APIs. Removing a loader does not delete previously accepted data; retention/deletion requires the documented operational workflow.

Installation does not certify production privacy, legal, security, infrastructure, or consent approval.

## Approved campaign codes and new analytics

In Installation, register public campaign codes (including `unknown`), select the primary registered CTA/action and choose whether generic diagnostics are approved. Set `campaign: "your-approved-code"` in the host context only after registering that code. Do not populate it with raw URL values or identifiers. A changed page revision must match both the host context and registry and needs its own reviewed reference; it creates a separate report cohort.

Reload your test page after installing the new immutable SDK/SRI or changing policy. Confirm Recorded activity, the ordered funnel and map coverage using your own clicks. Diagnostics require their page flag and consent; messages/stacks are excluded. Completed registrations need a separately approved backend integration. See [the analytics guide](ANALYTICS_UPGRADE.md).
